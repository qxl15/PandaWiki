# PandaWiki 专业版二次开发方案（阶段一可落地）

> 目标：在保持开源版核心能力兼容的前提下，完成专业版关键能力的基础落地。

## 1. 本次代码改造范围

- 后端授权与版本能力默认值：解除数量限制并默认打开专业能力开关。
- 后端核心校验：
  - 知识库数量限制改为可无限。
  - 管理员数量限制改为可无限。
  - 单知识库文档上限改为 10000。
  - 管理员分权相关接口不再拦截。
  - 统计时间维度限制不再按免费版拦截。
  - 文档细粒度权限编辑不再按 edition 拦截。
- 数据库：新增专业能力基础表结构（管理员 RBAC、审计日志、版权配置、AI 提示词模板/绑定/版本）。
- 性能：新增节点表组合索引，提升单 KB 10k 文档下目录与列表查询效率。

## 2. 新增文件清单

- `backend/store/pg/migration/000039_pro_features_foundation.up.sql`
- `backend/store/pg/migration/000039_pro_features_foundation.down.sql`
- `docs/professional-upgrade-plan.md`

## 3. 升级步骤（数据库）

1. 备份数据库。
2. 执行 migration up 至 `000039_pro_features_foundation.up.sql`。
3. 重启 API 服务。
4. 验证以下能力：
   - 可创建多个 KB。
   - 单 KB 可持续创建文档至 10000。
   - 可创建多个管理员。
   - 可配置 KB 用户多权限。
   - 统计接口支持 1/7/30/90 天。

## 4. 兼容性说明

- 现有数据不做破坏性变更。
- 仅新增表和索引，原有表字段保持不变。
- 限制改造采用“默认值 + 校验逻辑”方式，低耦合改动。

## 5. 后续阶段建议（未在本次提交中完整实现）

- 管理员权限管理页面与 API 完整 CRUD。
- 审计日志查询/导出 API 与前端页面。
- AI 提示词“目录级/文档级优先级”执行链路。
- 前台贡献审核流与 Diff 展示优化。
- 统计防刷（同 IP/用户周期去重）策略后台可配置化。
